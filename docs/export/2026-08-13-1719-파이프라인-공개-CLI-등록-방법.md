`[project.scripts]`는 **패키지 자신의 pyproject.toml**에 들어갑니다. 즉 루트 [pyproject.toml](pyproject.toml)이 아니라 [pipelines/pyproject.toml](pipelines/pyproject.toml)입니다. 루트에는 `[project]` 테이블 자체가 없고 `[tool.uv.workspace]`만 있어서 스크립트를 선언할 수 없습니다.

다행히 세 작업의 진입 함수가 이미 전부 **인자 없는 `main()`** 으로 준비돼 있습니다 — 이게 `[project.scripts]`가 요구하는 정확한 형태입니다.

| 작업 | 위치 |
|---|---|
| 수집 | [fetch_corpus.py:175](pipelines/src/pipelines/ingest/fetch_corpus.py#L175) |
| 청킹 | [chunker.py:135](pipelines/src/pipelines/chunk/chunker.py#L135) |
| 색인 | [build_index.py:113](pipelines/src/pipelines/index/build_index.py#L113) |

## 1단계 — pyproject.toml에 선언 추가

[pipelines/pyproject.toml](pipelines/pyproject.toml)의 `[project]` 블록 **바로 아래**에 추가합니다:

```toml
[project.scripts]
pipelines-ingest = "pipelines.ingest.fetch_corpus:main"
pipelines-chunk  = "pipelines.chunk.chunker:main"
pipelines-index  = "pipelines.index.build_index:main"
pipelines-query  = "pipelines.cli.query:main"
```

문법은 `명령이름 = "모듈경로:함수명"` 입니다. 콜론 왼쪽은 import 경로, 오른쪽은 호출할 함수입니다. 함수는 인자 없이 호출 가능해야 하고, 반환값은 종료 코드로 쓰입니다(`None`이면 0).

`pipelines-query`는 원래 요청에 있어서 같이 넣었습니다. `main()`이 `sys.argv[1:]`을 읽는데([query.py:48](pipelines/src/pipelines/cli/query.py#L48)) 콘솔 스크립트에서도 `sys.argv[0]`은 명령 이름이라 동작이 동일합니다.

## 2단계 — 재설치 (이 단계를 빠뜨리면 안 됩니다)

**콘솔 스크립트는 설치 시점에만 생성됩니다.** pyproject.toml만 고치면 명령이 생기지 않습니다. `.venv`에 pipelines를 다시 설치해야 실행 파일 shim이 만들어집니다.

```powershell
cd C:\PrivateLLM
uv sync
```

pipelines는 워크스페이스 멤버라 uv가 editable 모드로 설치합니다. 즉 이후 소스를 고쳐도 재설치 없이 바로 반영되지만, **`[project.scripts]` 항목을 추가·변경·삭제할 때만은 `uv sync`를 다시 돌려야** 합니다.

pipelines만 좁혀서 설치하려면 `uv sync --package pipelines`를 쓰세요.

## 3단계 — 확인 및 실행

설치되면 `.venv\Scripts\` 아래에 `.exe` shim이 생깁니다:

```powershell
ls .venv\Scripts\pipelines-*
```

실행:

```powershell
.venv\Scripts\Activate.ps1

pipelines-ingest                      # 수집 → data/raw
pipelines-chunk                       # 청킹 → data/chunks
pipelines-index                       # 색인 → data/chroma
pipelines-query "보증금을 못 받았어요"
```

활성화 없이도 됩니다: `.venv\Scripts\pipelines-chunk.exe`

## ⚠️ 환경변수는 여전히 필요합니다

콘솔 스크립트로 바꿔도 `.env`가 자동 로딩되지는 않습니다. 세 명령 모두 `Config.from_env()`를 호출하고, `LAW_API_OC`가 없으면 [config.py:70](pipelines/src/pipelines/config.py#L70)에서 `RuntimeError`로 죽습니다 — 수집뿐 아니라 **청킹·색인도 마찬가지**입니다. PowerShell에서는:

```powershell
$env:LAW_API_OC = "발급받은_키"
pipelines-chunk
```

이 불편을 없애려면 `python-dotenv`를 의존성에 추가하고 `Config.from_env()`에서 `.env`를 읽게 하는 방법이 있는데, 이건 별개 변경이라 지금 요청 범위 밖으로 두었습니다.

## 대안 — 명령 하나에 서브커맨드

명령 이름 4개가 흩어지는 게 싫다면 통합 진입점도 가능합니다. `pipelines/src/pipelines/cli/main.py`에 argparse 디스패처를 새로 만들고:

```toml
[project.scripts]
pipelines = "pipelines.cli.main:main"
```

```powershell
pipelines ingest
pipelines chunk
pipelines index
pipelines query "보증금을 못 받았어요"
pipelines --help          # 전체 파이프라인이 한눈에
```

**제 추천은 이쪽입니다.** `--help` 하나로 파이프라인 단계와 순서가 드러나고, 나중에 `--data-root` 같은 공통 옵션을 붙일 자리가 생깁니다. 대신 디스패처 모듈(약 40줄)을 새로 작성해야 합니다.

---

어느 쪽으로 구현해드릴까요? 개별 명령 4개(파일 수정 4줄, 새 코드 없음) 또는 통합 서브커맨드(디스패처 모듈 추가) 중 골라주시면 바로 작업하겠습니다.
