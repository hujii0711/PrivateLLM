`.venv`가 이미 있다고 가정하고 방법만 정리하겠습니다. 크게 두 갈래이고, **A만으로 충분한 경우가 대부분**입니다.

## 방법 A — 인터프리터 선택 (권장, launch.json 수정 불필요)

`Ctrl+Shift+P` → **`Python: Select Interpreter`** → 목록에서 `.venv` 항목 선택.

워크스페이스 루트의 `.venv`는 Python 확장이 자동 감지하므로 목록 맨 위쯤에 `('.venv': venv)` 표시와 함께 뜹니다. 안 보이면 `Enter interpreter path...`로 직접 지정합니다.

| OS | 실행 파일 경로 |
|---|---|
| Windows | `.venv\Scripts\python.exe` |
| macOS / Linux | `.venv/bin/python` |

선택하고 나면 `debugpy`가 그 인터프리터로 프로세스를 띄웁니다. [.vscode/launch.json](.vscode/launch.json)의 5개 구성 **전부에 자동 적용**되므로 파일을 고칠 필요가 없습니다.

확인 방법 두 가지:
- VS Code 하단 상태바에 현재 인터프리터가 표시됩니다.
- 디버그로 멈춘 상태에서 **디버그 콘솔**에 `import sys; sys.executable` 을 입력하면 실제 실행 중인 파이썬 경로가 나옵니다. 이게 가장 확실합니다.

## 방법 B — 구성별로 인터프리터 고정

특정 구성만 항상 `.venv`로 강제하고 싶을 때만 씁니다. 구성 객체에 `python` 키를 추가합니다.

```json
{
  "name": "Python: 현재 파일",
  "type": "debugpy",
  "request": "launch",
  "program": "${file}",
  "python": "${workspaceFolder}/.venv/Scripts/python.exe",
  "console": "integratedTerminal",
  "cwd": "${fileDirname}",
  "justMyCode": false
}
```

이 값은 방법 A의 선택보다 **우선합니다**. 다만 위 경로는 Windows 전용이라, 이 저장소처럼 macOS와 Windows를 오간다면 플랫폼별 분기를 쓰는 편이 안전합니다. `launch.json`은 `windows` / `osx` / `linux` 하위 블록을 지원합니다.

```json
  "python": "${workspaceFolder}/.venv/bin/python",
  "windows": {
    "python": "${workspaceFolder}/.venv/Scripts/python.exe"
  }
```

## settings.json은 어떻게 되나

[.vscode/settings.json:2](.vscode/settings.json#L2)의 `python.defaultInterpreterPath`(`.venv/bin/python`)는 **아직 인터프리터를 한 번도 고르지 않았을 때만** 참조되는 기본값입니다. 방법 A로 한 번 선택하면 그 선택이 워크스페이스 상태에 저장되어 이 설정보다 우선하므로, Windows에서 경로가 안 맞아도 실제 디버그에는 영향이 없습니다.

그래서 지금 상태로도 동작은 하지만, `defaultInterpreterPath`는 플랫폼별 분기를 지원하지 않는 단일 문자열 설정이라 Windows·macOS 양쪽에서 동시에 맞출 방법이 없습니다. 팀에서 양쪽 OS를 쓴다면 **이 줄을 아예 지우고** 자동 감지에 맡기는 편이 낫습니다. 어차피 루트 `.venv`는 확장이 알아서 찾습니다.
