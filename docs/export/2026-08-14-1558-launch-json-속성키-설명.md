`launch.json` 구성 객체의 속성들입니다. 앞의 4개는 **어떤 것을 어떻게 띄울지**, 뒤의 3개는 **띄운 뒤의 동작**을 정합니다.

| 키 | 값 | 역할 | 생략 시 |
|---|---|---|---|
| `name` | `"Python: 현재 파일"` | 드롭다운에 표시될 이름 | **필수** |
| `type` | `"debugpy"` | 이 구성을 처리할 디버거 종류 | **필수** |
| `request` | `"launch"` | 새로 실행 / 기존 프로세스에 접속 | **필수** |
| `program` | `"${file}"` | 실행할 스크립트 경로 | **필수** |
| `console` | `"integratedTerminal"` | 입출력을 붙일 위치 | 같은 값이 기본 |
| `cwd` | `"${fileDirname}"` | 작업 디렉터리 | `${workspaceFolder}` |
| `justMyCode` | `false` | 라이브러리 코드 진입 허용 여부 | `true` |

## 앞의 4개

**`name`** — 순수 표시용 라벨입니다. `Ctrl+Shift+D` 드롭다운에 이 문자열이 뜹니다. 디버그 동작에는 아무 영향이 없지만, 다른 구성에서 이 구성을 참조할 때는 이 이름이 키가 됩니다.

**`type`** — 어느 디버그 확장이 이 구성을 맡을지 지정합니다. `debugpy`는 `ms-python.debugpy` 확장을 가리키며, 이 확장은 [.vscode/extensions.json](.vscode/extensions.json)의 권장 목록에 이미 들어 있습니다. 예전 문서에서 보이는 `"type": "python"`은 구버전 이름으로, 지금도 동작하지만 `debugpy`로 넘어가는 것이 권장됩니다.

**`request`** — 두 가지 값만 있습니다.
- `"launch"` — VS Code가 파이썬 프로세스를 **새로 띄우고** 디버거를 붙입니다. 지금 쓰는 방식입니다.
- `"attach"` — 이미 돌고 있는 프로세스에 **나중에 붙습니다**. 서버처럼 이미 떠 있는 프로그램을 디버그할 때 씁니다.

**`program`** — 실행할 `.py` 파일의 경로입니다. `${file}`은 **지금 편집기에서 활성화된 파일의 절대경로**로 치환되는 VS Code 내장 변수입니다. 이 한 글자 차이가 이 구성을 범용으로 만듭니다. 아래 `20260814: yield_demo.py` 같은 구성들은 여기에 파일 경로가 박혀 있어서 늘 그 파일만 실행하지만, `${file}`은 열려 있는 아무 파일이나 실행합니다.

## 뒤의 3개

**`console`** — 프로그램의 표준 입출력을 어디에 연결할지 정합니다.

| 값 | 특징 |
|---|---|
| `integratedTerminal` | VS Code 통합 터미널. **`input()` 같은 표준 입력이 됩니다.** |
| `internalConsole` | 디버그 콘솔 패널. 출력은 보이지만 **입력이 불가능합니다.** |
| `externalTerminal` | 별도의 OS 터미널 창을 띄웁니다. |

`integratedTerminal`은 원래 기본값이라 사실 생략해도 같게 동작합니다. 명시해 둔 이유는 [xml_to_jsonl.py:210](python/20260814/xml_to_jsonl.py#L210)처럼 입력 인자를 `-`로 주면 `sys.stdin`을 읽는 코드가 있어서, 나중에 이 값을 실수로 바꾸면 그 경로가 막히기 때문입니다.

**`cwd`** — 프로그램이 실행될 작업 디렉터리입니다. 코드 안의 상대경로가 전부 이 기준으로 해석됩니다.

`${fileDirname}`은 **현재 파일이 들어 있는 폴더**입니다. 즉 [filter.py](python/edu/Example/basic/filter.py)를 디버그하면 `python/edu/Example/basic`이 되고, [yield_demo.py](python/20260814/yield_demo.py)를 디버그하면 `python/20260814`가 됩니다. 스크립트 옆에 있는 데이터 파일을 `open("data.txt")`처럼 짧게 열 수 있게 하려는 설정입니다. 지정하지 않으면 저장소 루트(`C:\PrivateLLM`)가 되어 같은 코드가 파일을 못 찾습니다.

**`justMyCode`** — 디버거가 **내 코드만 보여줄지**를 정합니다. 기본값은 `true`입니다.

- `true`: `F11`(스텝 인)을 눌러도 표준 라이브러리나 `site-packages` 안으로는 들어가지 않고 통과합니다. 라이브러리 내부에서 난 예외도 그냥 지나갑니다.
- `false`: 라이브러리 내부까지 들어가고, 그 안에 중단점도 걸 수 있습니다.

여기서 `false`로 둔 것은 `python/20260814`의 파일들이 제너레이터와 `iterparse` 동작을 학습하려는 코드이기 때문입니다. `yield`가 어떻게 일시정지·재개되는지, `iterparse`가 어느 시점에 이벤트를 내보내는지는 라이브러리 안으로 들어가 봐야 보입니다.

다만 한계가 있습니다. `filter`나 `list`처럼 **C로 구현된 내장 함수**는 파이썬 코드가 아니라서 `justMyCode: false`여도 스텝 인이 되지 않습니다. 파이썬으로 작성된 라이브러리에만 해당합니다.
