코드베이스를 확인했습니다. 이 시스템은 **Python(FastAPI) 백엔드 + Next.js 프론트엔드** 모노레포 구조입니다. 별도의 통합 실행 스크립트는 없고, 백엔드/프론트엔드를 각각 띄우는 방식입니다.

## 시스템 구성

| 구성요소 | 위치 | 포트 | 역할 |
|---------|------|------|------|
| **API 서버** | [apps/api/](apps/api/) | 8000 | FastAPI + MLX(Qwen2.5-7B) + Chroma RAG, `POST /chat` SSE 스트리밍 |
| **웹** | [apps/web/](apps/web/) | 3000 | Next.js 16 채팅 UI, `NEXT_PUBLIC_API_BASE`로 API 호출 |

웹은 [.env.local](apps/web/.env.local)의 `NEXT_PUBLIC_API_BASE=http://localhost:8000`로 백엔드를 바라봅니다.

---

## 개발 모드 (Dev)

핫리로드가 켜진 상태로, 터미널 2개를 사용합니다.

**① 백엔드** — [apps/api/](apps/api/)
```bash
cd apps/api
uv run uvicorn --app-dir src api.main:app --reload --port 8000
```
- `--app-dir src` : 패키지가 `src/api/` (src 레이아웃)에 있어 필요
- `--reload` : 코드 변경 시 자동 재시작
- 첫 요청 시 MLX 모델·Chroma 리트리버를 지연 로딩합니다 ([main.py:47-58](apps/api/src/api/main.py#L47-L58))

**② 프론트엔드** — [apps/web/](apps/web/)
```bash
cd apps/web
npm run dev          # next dev, http://localhost:3000
```

→ 브라우저에서 http://localhost:3000 접속

## 운영 모드 (Prod)

**① 백엔드** — `--reload` 끄고 외부 바인딩
```bash
cd apps/api
uv run uvicorn --app-dir src api.main:app --host 0.0.0.0 --port 8000
```
> ⚠️ `--workers` 다중화는 권장하지 않습니다. 워커마다 MLX 7B 모델을 메모리에 따로 로딩하므로 메모리가 급증합니다. 단일 워커 유지를 권장합니다.

**② 프론트엔드** — 빌드 후 프로덕션 서버
```bash
cd apps/web
npm run build        # next build
npm run start        # next start, http://localhost:3000
```

## 사전 준비 (최초 1회)


## 환경변수

| 변수 | 적용 | 기본값 | 비고 |
|------|------|--------|------|
| `MLX_MODEL` | API | `mlx-community/Qwen2.5-7B-Instruct-4bit` | 모델 교체 시 ([settings.py:6](apps/api/src/api/settings.py#L6)) |
| `CHROMA_DIR` | API | `<repo>/data/chroma` | 색인 위치 변경 시 ([config.py](packages/rag/src/rag/config.py)) |
| `NEXT_PUBLIC_API_BASE` | Web | `http://localhost:8000` | 운영 시 실제 API 도메인으로 변경 |

---

정리하면 — **개발**은 `uvicorn ... --reload` + `npm run dev`, **운영**은 `uvicorn`(reload 없이) + `npm run build && npm run start` 조합입니다.

참고로 현재는 매번 두 명령을 따로 입력해야 하는데, 원하시면 한 번에 띄우는 **`Makefile`이나 통합 실행 스크립트(dev/prod 타깃)를 추가**해 드릴 수 있습니다. 필요하시면 말씀해 주세요.
