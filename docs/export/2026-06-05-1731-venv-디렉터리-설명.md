`.venv`는 **Python 가상환경(virtual environment)** 디렉터리입니다. 이 프로젝트의 의존성과 Python 인터프리터가 시스템 전역과 분리되어 격리 설치되는 공간으로, 여기서는 **uv가 워크스페이스 전체를 위해 만든 단일 가상환경**입니다.

## 역할

- **의존성 격리** — `pyproject.toml`에 선언된 패키지(`fastapi`, `chromadb`, `mlx-lm` …)를 시스템 Python이 아닌 이 디렉터리 안에 설치합니다. 다른 프로젝트나 OS Python을 오염시키지 않습니다.
- **고정된 Python 버전** — `pyvenv.cfg`를 보면 uv가 받아온 **CPython 3.11.15**를 사용 (`requires-python = ">=3.11"` 충족). 시스템에 어떤 Python이 깔려 있든 이 버전으로 동작.
- **워크스페이스 공유 환경** — uv 워크스페이스라서 루트 `.venv` 하나에 모든 멤버(`rag`, `api`, `eval`, `finetune`, `ftdata`)가 **editable install**로 들어가 서로 import 가능. (`pipelines/.venv`는 별도로 한 번 만들어진 흔적)

## 주요 내부 구조

| 항목 | 내용 |
|------|------|
| `bin/` | `python`, `pip`, `uvicorn`, `pytest` 등 실행 파일 (활성화 시 PATH 맨 앞에 추가) |
| `lib/python3.11/site-packages/` | 설치된 모든 패키지 실제 코드 |
| `pyvenv.cfg` | 이 venv의 메타데이터 (Python 경로·버전·생성 도구 uv 0.11.7) |

## 이 프로젝트에서

- 크기 **약 1.2G** — `mlx-lm`, `sentence-transformers`, `chromadb` 등 ML 라이브러리가 무거워서 큽니다.
- [.gitignore](.gitignore#L6)에 `.venv/`가 등록 → **커밋되지 않음.** 환경은 코드가 아니라 `pyproject.toml` + `uv.lock`으로 재현하는 것이 원칙.

## 관리 / 재생성

- 직접 만들지 말고 **uv가 관리하게 두는 것**이 정석:
  - `uv sync` — `uv.lock` 기준으로 `.venv`를 생성·동기화 (없으면 새로 만듦).
  - `uv run <명령>` — `.venv`를 자동 활성화한 채 명령 실행 (수동 `source` 불필요).
- **삭제해도 안전** — `rm -rf .venv` 후 `uv sync`로 그대로 복원됩니다. 캐시처럼 언제든 재생성 가능한 산출물입니다.

## `.pytest_cache`와의 차이

- `.pytest_cache` = pytest 실행 기록용 **가벼운 캐시** (수 KB).
- `.venv` = 실제 **실행 환경 전체** (수 GB). 둘 다 git에 안 올라가고 재생성 가능하다는 공통점은 있지만, 후자가 없으면 코드를 아예 실행할 수 없습니다.

요약하면, `.venv`는 **이 프로젝트 전용으로 격리된 Python 실행 환경**이며, `pyproject.toml`/`uv.lock`으로부터 `uv sync`로 언제든 재현되는 비버전관리 산출물입니다.
