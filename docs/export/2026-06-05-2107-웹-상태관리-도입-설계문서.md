# apps/web 상태 관리 도입 설계 문서

## 1. 목적
향후 고도화(대화 세션 관리 · 사용자/인증 · UI 상태 확대 · 실시간/협업)를 대비해, `apps/web`에 **서버 상태와 클라이언트 상태를 분리 관리**하는 인프라를 도입한다. 라이브러리는 **react-query(서버 상태) + zustand(클라이언트 상태)** 조합을 채택한다.

## 2. 배경 및 현황
- **스택**: Next.js 16 + React 19 (App Router), 상태 라이브러리 전무
- 채팅 상태는 [useChat.ts](apps/web/hooks/useChat.ts)의 `useState`(`messages`/`busy`)에만 존재
- 데이터는 [chatClient.ts](apps/web/lib/chatClient.ts)의 **SSE 스트리밍**(`POST /chat`)으로 직접 처리
- 컴포넌트 트리는 얕은 props drilling (`Chat → MessageBubble/ChatInput`)
- 캐싱·세션 영속화·인증 없음

## 3. 핵심 설계 원칙

> **결정의 본질은 "zustand냐 redux냐"가 아니다.** react-query가 서버 상태를 가져가면, 클라이언트 전역 상태로 남는 영역이 작아진다. 그래서 redux는 과설계이고 zustand가 적합하다.

**단일 출처 원칙(SSOT)**: 서버 데이터(세션 목록, 사용자 정보)는 **react-query 캐시가 유일한 출처**다. zustand에 복사·미러링하지 않는다. zustand에는 "활성 세션 ID" 같은 *참조/선택 상태*와 UI 토글만 둔다.

## 4. 아키텍처 — 역할 분담

| 영역 | 상태 성격 | 담당 |
|---|---|---|
| 세션 목록/저장/전환, 메시지 히스토리 영속화 | 서버 상태 (캐싱·동기화·무효화) | **react-query** |
| 사용자/인증 (me, 프로필, 권한, 사용량) | 서버 상태 | **react-query** |
| 활성 세션 ID, 사이드바, 다크모드, 모달, 입력 draft | 클라이언트 UI 상태 | **zustand** |
| 실시간/협업 | 서버 상태 동기화 + UI presence | react-query `setQueryData` + 소켓 레이어, presence UI만 zustand |
| 진행 중 스트리밍 토큰 버퍼 | 일시적 클라이언트 상태 | useChat(로컬) |

## 5. 라이브러리 선택 근거 (요약)

**zustand 채택**
- react-query가 서버 상태를 가져가 **남는 전역 상태가 작음** → redux의 구조 강제/미들웨어/타임트래블 이점이 비용 대비 낮음
- 보일러플레이트 최소, 셀렉터 기반 구독으로 리렌더 자연 차단
- `devtools` 미들웨어로 redux devtools 디버깅 이점 일부 흡수
- 실시간/협업도 reducer가 아닌 *소켓 → react-query 캐시 갱신*이 표준

**redux가 맞는 반례(정직하게)**: 클라이언트 상태가 복잡하게 상호의존하고, 대규모 팀이 같은 상태를 동시에 만지며, 액션 타임트래블 디버깅이 상시 필요할 때. 현재 로드맵엔 해당 없음.

## 6. 구현 상세 (도입 완료분)

| 파일 | 역할 | 핵심 결정 |
|---|---|---|
| [app/providers.tsx](apps/web/app/providers.tsx) *(신규)* | `'use client'` QueryClient Provider | TanStack 공식 SSR 패턴(`isServer` 분기): **서버는 매 요청 새 클라이언트 → 사용자 간 캐시 누수 차단**, 브라우저는 싱글톤. dev에서만 devtools |
| [store/uiStore.ts](apps/web/store/uiStore.ts) *(신규)* | zustand UI store | `activeSessionId`/`sidebarOpen`/`theme`만. `persist`는 UI 환경설정만 영속화, `devtools` 연결. SSOT 위반 금지 주석 |
| [test/renderWithProviders.tsx](apps/web/test/renderWithProviders.tsx) *(신규)* | 테스트 래퍼 | `retry:false` QueryClient + `resetUiStore()`로 테스트 간 상태 누수 차단 |
| [app/layout.tsx](apps/web/app/layout.tsx) *(수정)* | Provider 래핑 | Next.js 16 docs 권장대로 `<html>` 전체가 아닌 `{children}`만 감싸 정적 최적화 보존 |
| [package.json](apps/web/package.json) *(수정)* | 의존성 | `@tanstack/react-query` ^5.101, `zustand` ^5.0, devtools(dev) |

**불변(경계 유지)**: [lib/chatClient.ts](apps/web/lib/chatClient.ts), [lib/sse.ts](apps/web/lib/sse.ts), [lib/types.ts](apps/web/lib/types.ts) — SSE 스트리밍 로직은 손대지 않음.

## 7. 위험 요소 및 대응

| 위험 | 대응 |
|---|---|
| **react-query ↔ SSE 불일치** (최우선) | `useQuery`에 스트림을 끼우지 않음. 스트리밍은 명령형 유지, `done` 시점에 완성 메시지를 `setQueryData`로 캐시 반영 |
| **App Router SSR 요청 간 누수** | QueryClient 모듈 싱글톤 금지 → `isServer` 분기로 요청별 생성 (구현 완료) |
| **SSOT 위반** | 서버 데이터를 zustand에 복사 금지 — store엔 참조/선택 상태만 |
| **인증 결합** | 토큰·401 리프레시·SSR 쿠키 → 서버 프리패치 + `HydrationBoundary` 패턴 |
| **테스트 영향** | `renderWithProviders` 래퍼 + `resetUiStore()` (구현 완료) |

## 8. 향후 확장 로드맵 (점진 도입)
백엔드 엔드포인트 준비 순서대로:
1. **세션 관리**: `hooks/queries/useSessions.ts`(`useQuery`) + useChat `done→setQueryData`
2. **인증**: `hooks/queries/useMe.ts` + 서버 프리패치/`HydrationBoundary`
3. **UI 확대**: uiStore에 모달/설정 패널 상태 추가
4. **실시간/협업**: 웹소켓 레이어 + 소켓 이벤트 → 캐시 갱신 규약
