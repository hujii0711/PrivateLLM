`apps/api/src/api`의 6개 파일은 이미 전부 읽어 두었습니다. 이를 바탕으로 동작 방식과 상호관계를 분석합니다.

## 1. 모듈별 책임 (한 줄 요약)

| 파일 | 책임 | 의존(임포트) |
|---|---|---|
| [__init__.py](apps/api/src/api/__init__.py) | 패키지 표식(빈 파일) | — |
| [schemas.py](apps/api/src/api/schemas.py) | 입출력 데이터 계약(pydantic) | pydantic |
| [settings.py](apps/api/src/api/settings.py) | 구성값(모델·토큰·온도·RAG) | `rag.config.RagConfig` |
| [llm.py](apps/api/src/api/llm.py) | LLM 추상화 + MLX 구현 | `mlx_lm`(지연), `.settings` |
| [pipeline.py](apps/api/src/api/pipeline.py) | RAG 오케스트레이션(`run_chat`) | `rag.citations`, `rag.prompt` |
| [main.py](apps/api/src/api/main.py) | FastAPI 앱·엔드포인트·DI·캐싱 | `.pipeline`, `.schemas`, `.settings`, `rag.retriever`, `.llm` |

## 2. 의존 그래프 (방향 = "A가 B를 사용")

```
                         main.py  ◀── (uvicorn api.main:app)
                        /   |   |   \
                       /    |   |    \
                schemas  settings  pipeline   llm
                            |         |   \     |
                       rag.config   rag.   rag. (mlx_lm)
                                    prompt citations
```

핵심 관찰:
- **main.py가 유일한 조립 지점(composition root)** — 나머지를 모두 끌어와 연결합니다.
- **pipeline.py는 llm·settings를 직접 임포트하지 않습니다.** 인자로 `retriever`, `llm`을 **주입받습니다**(느슨한 결합). 그래서 pipeline은 MLX인지 vLLM인지 모릅니다.
- **순환 의존 없음.** llm·pipeline은 서로를 모르고, main이 둘을 잇습니다.
- `rag` 패키지(검색·프롬프트·인용)에 단방향 의존. api는 rag의 소비자.

## 3. 두 가지 핵심 추상화

### (A) `LLM` Protocol — 백엔드 교체 지점 ([llm.py](apps/api/src/api/llm.py))

```python
class LLM(Protocol):
    def stream(self, messages, *, max_tokens=768, temperature=0.3) -> Iterator[str]: ...
```

- **구조적 타이핑(Protocol)**: `stream` 시그니처만 맞으면 LLM으로 간주. 상속 불필요.
- 구현 3종: `MlxLLM`(실제 Qwen), `FakeLLM`(테스트용 고정 토큰), 그리고 배포 문서의 신규 `OpenAICompatLLM`이 여기 꽂힙니다 → **이 Protocol이 "단일 코드베이스·3배포"의 기술적 근거**.
- `MlxLLM`은 `from mlx_lm import ...`를 **메서드 내부에서 지연 임포트** → mlx 미설치 환경(웹 테스트, CI)에서도 모듈 임포트 자체는 실패하지 않음.

### (B) 의존성 주입 + 지연 캐싱 ([main.py](apps/api/src/api/main.py))

```python
def create_app(retriever=None, llm=None, settings=None) -> FastAPI:
    ...
    app.state.retriever = retriever   # 테스트는 Fake 주입
    app.state.llm = llm
```

- `create_app(retriever=, llm=)`로 **테스트 시 가짜 객체 주입**, 미주입(`app = create_app()`)이면 실제 구성.
- `/chat` 핸들러에서 `app.state.retriever or _build_retriever(...)` — 주입 우선, 없으면 실제 빌드.
- `_build_retriever`/`_build_llm`은 **함수 속성에 캐싱**(`if not hasattr(..., "_cached")`) → 무거운 모델·임베더를 **첫 요청 1회만 로드**(콜드스타트), 이후 재사용. 모듈 import 시점이 아니라 첫 호출 시 로드되는 **지연 초기화**.

## 4. 요청 한 건의 전체 흐름 (`POST /chat`)

```
클라이언트 POST {message}
   │
   ▼ [main.py] FastAPI가 ChatRequest로 검증 (schemas.py, min_length=1)
   │
   ▼ retriever = app.state.retriever or _build_retriever(settings)   # 캐시 로드
   │  model    = app.state.llm or _build_llm(settings)
   │
   ▼ EventSourceResponse(event_gen())  ← SSE 시작
   │
   └─▶ [pipeline.py] run_chat(message, retriever, llm, max_tokens, temperature):
         1. hits = retriever.retrieve(query)            # rag: bge-m3 → Chroma top-k
         2. if not retriever.is_grounded(hits):         # top1 유사도 < 0.35
              → NO_GROUNDING_MSG(거절) + 면책 → done, return   ★조기 종료
         3. messages = build_messages(query, hits)      # rag.prompt: 시스템+번호근거
         4. for tok in llm.stream(messages, ...):       # llm: 토큰 스트리밍
              yield {"type":"token","text":tok}         #   → main이 SSE data로 감쌈
         5. raw = "".join(parts)
            answer = _ensure_disclaimer(               # 면책 결정적 보장
                       strip_invalid_citations(raw, hits))  # rag: 환각 [n] 제거
            sources = extract_sources(answer, hits)     # rag: 유효 [n] → Source
         6. yield {"type":"done","answer":..,"sources":[..]}
         │
   ◀─────┘ [main.py] 각 이벤트를 {"data": json.dumps(ev)} 로 변환 → 클라이언트
```

- **main의 `event_gen`은 얇은 변환층**: pipeline의 dict 이벤트를 SSE `data:` 프레임으로 직렬화(`ensure_ascii=False`로 한글 보존)만 함. 비즈니스 로직은 전부 pipeline.
- **두 갈래 종료 경로**: ②근거 부족 거절(LLM 호출 안 함) / ⑥정상 답변. 둘 다 반드시 `done` + 면책으로 끝남.

## 5. 책임 분리가 만들어내는 성질

| 설계 선택 | 효과 |
|---|---|
| pipeline이 retriever·llm을 **주입받음** | 백엔드(MLX/vLLM)·검색 구현 교체가 pipeline 코드 변경 0 |
| `LLM` **Protocol** | 배포 환경별 구현만 추가([02](docs/superpowers/release/02-linux-gpu.md) `OpenAICompatLLM`) |
| **지연 import + 지연 캐싱** | 모델 없는 환경서 import 가능, 모델은 첫 요청 1회 로드 |
| pipeline이 **순수 제너레이터**(dict yield) | 평가 하니스(`packages/eval`)가 `run_chat`을 그대로 재사용 → "서빙=평가 동일" |
| 면책·인용검증을 **pipeline에서 결정적 처리** | 모델 출력 품질과 무관하게 안전장치 보장 |
| settings가 `rag.config`를 **포함(compose)** | API 설정과 RAG 설정이 한 객체로 일관 주입 |

## 6. 결합도 평가 & 개선 여지

**강점**: main(조립) → {schemas, settings, pipeline, llm} 의 **별 모양 의존**으로, 잎 모듈(schemas·llm·pipeline)끼리는 서로 모릅니다. 테스트 용이성·교체 용이성이 높습니다.

**개선 여지(배포 문서 §6과 연결)**:
- `event_gen`에 **try/except 없음** → llm.stream 예외 시 SSE가 잘려 끝남. `{"type":"error"}` 이벤트 필요(C3).
- `_build_*`의 함수 속성 캐싱은 단순하나 **테스트 간 상태 공유** 위험(프로세스 전역). 운영엔 무해하나 `app.state`로 옮기면 더 깔끔.
- CORS가 main에 하드코딩 → `CORS_ORIGINS` env화(C2).
- `schemas.SourceOut`은 정의됐으나 **응답에 미연결**(pipeline은 dict로 sources 반환) → 타입 계약 강화 여지.
- pipeline의 `temperature` 기본값(0.3)과 settings(0.2) 불일치 — main이 `cfg.temperature`(0.2)를 명시 전달하므로 운영은 0.2, 단 기본값 표기는 정리 대상.
