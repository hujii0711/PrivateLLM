# mermaid 다이어그램 뷰잉 환경 — 설계 문서

- **작성일:** 2026-07-31
- **상태:** 승인됨
- **목적:** 대화로만 존재하던 아키텍처 다이어그램을 저장소에 보존하고, VS Code에서 그림으로 확인

---

## 1. 배경

아키텍처 분석 과정에서 mermaid 다이어그램 3종을 작성했으나 다음 문제가 있다.

1. **렌더링 불가** — VS Code 기본 마크다운 미리보기는 mermaid를 지원하지 않아 코드 블록 원문만 보인다.
2. **유실 위험** — 모듈 의존 그래프는 대화에만 존재하고 파일로 저장되지 않았다.
3. **탐색 곤란** — 저장된 다이어그램도 `docs/export/`의 날짜별 대화 기록에 섞여 있어 찾기 어렵다.

## 2. 목표

- VS Code에서 `Ctrl+Shift+V`로 다이어그램을 그림으로 확인한다.
- 다이어그램 3종을 단일 문서에 모아 저장소에 보존한다.
- 빌드 단계·실행 서버·외부 네트워크 의존을 만들지 않는다.

### 비범위 (Out of Scope)

- 다이어그램 이미지(PNG/SVG) 파일 생성 — `mermaid-cli`는 Chromium 다운로드가 필요해 과하다.
- 단독 HTML 뷰어 — VS Code 미리보기로 충분하다.
- CI 렌더링 검증 — 이 저장소는 git 저장소가 아니라 적용 대상이 없다.

## 3. 구성 요소

| 구성 | 대상 | 변경 내용 |
|---|---|---|
| VS Code 확장 | 로컬 환경 | `bierner.markdown-mermaid` 설치 |
| 확장 추천 | `.vscode/extensions.json` | `recommendations` 배열에 1줄 추가 |
| 다이어그램 허브 | `docs/ARCHITECTURE.md` | 신규 생성 |

기존 코드·설정·의존성은 변경하지 않는다.

### 3.1 확장 선택 근거

`bierner.markdown-mermaid`는 VS Code **내장** 마크다운 미리보기에 mermaid 렌더러만 추가한다.
별도 프리뷰 창·서버·빌드가 없어 기존 워크플로가 그대로 유지되고,
저장소의 모든 `.md` 파일에 자동 적용되므로 향후 작성할 다이어그램도 추가 설정 없이 렌더링된다.

## 4. 문서 구조

`docs/ARCHITECTURE.md`는 다음 3개 절로 구성한다.

| 절 | 다이어그램 | 내용 |
|---|---|---|
| §1 | `graph TB` | 시스템 전체 구조 — 오프라인 파이프라인 / 서빙 / 품질 루프 |
| §2 | `graph LR` | 모듈 의존 그래프 — 패키지별 subgraph, 경계 넘는 의존 |
| §3 | `graph LR` | 구축 실행 절차 — 0~5단계 흐름 |

각 다이어그램 아래에 한 줄 설명과 관련 소스 파일 링크를 단다.

### 4.1 `docs/export/`와의 역할 분리

`docs/export/`의 대화 기록은 **수정하지 않는다.**

- `docs/export/` — 특정 시점의 대화 스냅샷. 불변 기록.
- `docs/ARCHITECTURE.md` — 최신 상태를 반영하는 살아있는 문서. 구조 변경 시 갱신 대상.

내용이 일부 중복되지만, 기록 보존과 최신성 유지는 목적이 다르므로 분리를 유지한다.

## 5. mermaid 문법 규약

미리보기 렌더링 실패를 막기 위해 다음 규약을 따른다.

1. **노드 라벨의 괄호는 제거하거나 `["..."]`로 감싼다.** `A[pipelines (독립)]`처럼 라벨에 괄호가
   있으면 파서가 노드 모양 문법으로 오인해 실패한다. 한글 자체는 문제없다.
2. **`classDef`·`style` 지시문을 쓰지 않는다.** 확장 버전에 따라 동작이 달라진다.
3. **화살표 표기 범례를 다이어그램 아래에 명시한다.**
   - `-->` 일반 의존
   - `==>` 패키지 경계를 넘는 의존
   - `-.->` 함수 내부의 지연 import

## 6. 검증

렌더링 결과는 화면으로만 확인 가능하므로 **사용자 수동 검증**으로 처리한다.

```
1) 확장 설치 후 VS Code 재시작
2) docs/ARCHITECTURE.md 열고 Ctrl+Shift+V
3) 다이어그램 3개가 모두 그림으로 표시되는지 확인
```

**실패 판정:** 다이어그램 자리에 빨간 에러 박스가 표시되면 §5 규약 위반이다. 해당 블록을 수정한다.

## 7. 리스크

| 리스크 | 대응 |
|---|---|
| 확장 설치 실패 (오프라인 등) | 실패 시 사용자에게 보고하고 VS Code 마켓플레이스 UI 수동 설치 안내 |
| mermaid 문법 오류 | §5 규약 준수 + 사용자 검증 게이트에서 확인 후 수정 |
| 구조 변경 시 문서 노후화 | `ARCHITECTURE.md`가 갱신 대상임을 문서 상단에 명시 |
