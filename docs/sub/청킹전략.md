### 전략 개요: **구조 인지(Structure-Aware) 청킹**

일반적인 "고정 토큰 수로 자르기" 방식이 아닌, **문서의 논리 구조 단위**를 청킹 경계로 삼는 방식을 사용합니다.

---

### 전략 1: 법령 → `chunk_law()` — **조문(Article) 단위 청킹**

```
법령 1건 JSON
  └── articles[] 배열
        ├── 제1조 → Chunk 1
        ├── 제2조 → Chunk 2
        └── 제N조 → Chunk N
```

| 항목 | 내용 |
|------|------|
| **분할 단위** | 조문 1개 = Chunk 1개 |
| **id 패턴** | `law-{법령명}-{조문번호}` (예: `law-주택임대차보호법-제3조의2`) |
| **title** | `법령명 조문번호(조문제목)` — 검색 결과에서 출처가 바로 보이게 구성 |
| **근거** | 조문이 법령 검색·인용의 자연스러운 최소 단위이기 때문 |

---

### 전략 2: 판례 → `chunk_prec()` — **핵심 섹션 선별 청킹**

```
판례 1건 JSON
  ├── holding_summary (판시사항)  → Chunk A
  ├── judgment_summary (판결요지) → Chunk B
  └── body (본문 전문)            → ❌ 저장 안 함
```

| 항목 | 내용 |
|------|------|
| **분할 단위** | 핵심 요약 섹션 2개만 선별 저장 |
| **id 패턴** | `prec-{판례ID}-{섹션명}` (예: `prec-98765-판시사항`) |
| **빈 섹션** | 내용 없으면 Skip → 색인 품질 보호 |
| **근거** | 판례 전문은 길고 잡음이 많아 LLM 답변 근거로 부적합한 부분 제외 |

---

### 공통 전처리: `normalize_text()`

청킹 전 **모든** 텍스트에 적용:

```
소프트 하이픈 제거 (­)
  → 특수 공백(&nbsp;) → 일반 공백
  → 줄바꿈 \r\n / \r → \n 통일
  → 줄 내 연속 공백/탭 → 단일 공백
  → 빈 줄 제거
```

---

### Chunk 공통 스키마

```python
class Chunk(TypedDict):
    id: str          # 유일 식별자
    text: str        # 임베딩 대상 본문
    source_type: str # "법령" | "판례" | "해설" | "상담사례"
    title: str       # 검색 결과 표시용 제목
    ref: str         # 조문번호 or 섹션명
    url: str         # 원문 URL
    date: str        # YYYY-MM-DD
```

### 전략의 설계 포인트 요약

| 포인트 | 법령 | 판례 |
|--------|------|------|
| 청킹 기준 | 구조적 단위 (조문) | 의미적 선별 (핵심 요약만) |
| 길이 제어 | 별도 없음 (조문 크기 = 자연 경계) | 섹션 선별로 암묵적 제어 |
| 빈 데이터 처리 | 조문 제목 optional | 빈 섹션 Skip |
| 검색 최적화 | 법령명+조문번호를 title에 포함 | 법원+사건번호를 title에 포함 |

**현재 미구현된 source_type**: `schema.py`에 `"해설"`, `"상담사례"` 타입이 선언되어 있지만, 아직 대응하는 청킹 함수가 없습니다. 향후 확장 예정으로 보입니다.
